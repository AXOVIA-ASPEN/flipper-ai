Release Roadmap · Four Phases

15 features, four releases, one git tag to GA

The mobile track sequences Features 15–29 into four phases, each ending in a real release to real devices. The delivery pipeline is built first — so from Phase B onward, every merged story is on testers' phones within minutes.

15 features 80 stories 4 release milestones Target: v2.0.0 on App Store + Google Play
Fastest-path principle: Phase A stands up the monorepo, the CI/CD pipeline, and the auth bridge before any feature work. A stub-but-real binary reaches TestFlight and Firebase App Distribution at the end of Phase A — everything after that ships continuously.

Hot-fixes in minutes, not weeks

Over-the-air JavaScript updates ship fixes in ≤ 30 minutes — no App Review wait. Production rollouts phase 10% → 25% → 50% → 100% with bake time at each stage.

FR-RELEASE-MOBILE-10 · NFR-MOB-RELEASE-01
⏪

One-command rollback

A documented rollback re-publishes the prior stable update in ≤ 5 minutes if a regression slips through — with the procedure runbooked for operations.

FR-RELEASE-MOBILE-11
🛡️

Force-upgrade floor

The backend declares a minimum supported version per platform; older installs see an upgrade screen deep-linked to the store — no zombie clients against a moving API.

FR-RELEASE-MOBILE-12
Backend stays untouched at v1: the mobile app consumes the existing Cloud Run API — same scraper jobs, opportunities, messages, posting queue, and analytics endpoints the web uses. The only backend additions are the Bearer-token bridge, a device-token model for push, and the purchase webhook. Web and mobile stay in lock-step by construction.
