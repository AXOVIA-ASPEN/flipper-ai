Foundation & Shared Platform

PHASE AFeature 15

One codebase family: the mobile workspace lives beside the web app, sharing types, design tokens, and tooling.

FR-MOBILE-FOUNDATION-01

Repository becomes a pnpm workspace monorepo with a dedicated mobile/ workspace and shared packages/ beside the existing web app.

FR-MOBILE-FOUNDATION-02

Mobile app is built on Expo (SDK 53+, managed workflow) with file-based routing that mirrors the web's route structure.

FR-MOBILE-FOUNDATION-03

TypeScript strict mode throughout, extending the project base config and path-alias conventions.

FR-MOBILE-FOUNDATION-04

Shared domain types (Listing, Opportunity, ScraperJob, User, Message, PostingJob…) extracted to a shared package consumed by both web and mobile — no duplication.

FR-MOBILE-FOUNDATION-05

Design tokens (color, spacing, radius, typography, glass-surface values) extracted to a framework-agnostic package feeding both web Tailwind and mobile styling.

FR-MOBILE-FOUNDATION-06

NativeWind renders the canonical dark-glassmorphism design language natively — purple #7c3aed accent on the #080b14 dark surface, glass cards and glow treatments included.

FR-MOBILE-FOUNDATION-07

Every mobile source file carries the project's standard file header (author, description, copyright).

FR-MOBILE-FOUNDATION-08

ESLint config inherits the project root rules plus React Native/Expo plugins; one lint command covers web and mobile.

FR-MOBILE-FOUNDATION-09

Prettier formatting matches the project root across both workspaces.

FR-MOBILE-FOUNDATION-10

Make targets for every mobile workflow: dev, test, e2e, iOS/Android builds, store submission.

FR-RELEASE-MOBILE-05

Preview builds auto-distribute to TestFlight internal testers (iOS) and Firebase App Distribution groups (Android).

FR-RELEASE-MOBILE-06

FR-RELEASE-MOBILE-07

Over-the-air JavaScript updates between binary releases, with production rollouts phased 10% → 25% → 50% → 100%.

Sign-In & Onboarding

PHASE AFeature 17

Same identity as the web — sign in once, stay signed in, optionally unlock with a face or fingerprint.

FR-MOBILE-AUTH-01

Mobile authenticates against the same Firebase project as the web app — identical user identity on every device.

FR-MOBILE-AUTH-02

API calls carry the Firebase ID token as a Bearer header; the existing backend accepts it alongside the web session cookie.

FR-MOBILE-AUTH-03

Tokens persist in iOS Keychain / Android Keystore with automatic refresh — users stay signed in across launches.

FR-MOBILE-AUTH-04

Email/password sign-up and sign-in, password reset, and OAuth with Google and Apple (Apple is required by App Store policy).

FR-MOBILE-AUTH-05

Optional biometric re-authentication (Face ID / Touch ID / Android biometrics) that unlocks a cached session — never replaces the credential.

FR-MOBILE-AUTH-06

Sign-out clears the secure token store and local caches, then returns to the auth stack.

FR-MOBILE-AUTH-07

The 6-step onboarding wizard reflows for touch — swipe between steps, progress dots, skippable — and syncs to the same backend so onboarding once counts everywhere.

FR-MOBILE-AUTH-08

An auth guard redirects unauthenticated users to sign-in, mirroring the web's provider pattern.

FR-MOBILE-AUTH-09

Abuse protection (hCaptcha or App Check) on sign-up and password-reset, at parity with the web.

FR-MOBILE-AUTH-10

Authentication events leave diagnostic breadcrumbs in crash reporting (never tokens or PII).

FR-MOBILE-LIFECYCLE-08

Subscriptions (In-App Purchase)

PHASE CFeature 25

Native store billing reconciled to one backend tier record — never double-billing a web subscriber.

FR-MOBILE-BILLING-01

Subscriptions sell through Apple StoreKit / Google Play Billing (mediated by RevenueCat) — no web-checkout workarounds, per store policy.

FR-MOBILE-BILLING-02

IAP tiers mirror the web: FREE, FLIPPER (monthly + annual), PRO (monthly + annual), with consistent product identifiers in both stores.

FR-MOBILE-BILLING-03

Purchase webhooks update the same backend subscription record that web Stripe purchases use — one source of truth.

FR-MOBILE-BILLING-04

Web subscribers are never charged again on mobile — their tier is honored automatically and no upsell is shown.

FR-MOBILE-BILLING-05

Subscription management and cancellation deep-link to the OS-level subscription settings.

FR-MOBILE-BILLING-06

Tier-based feature gating matches the web; gates render client-side as UX but the server is authoritative.

FR-MOBILE-BILLING-07

The App Store-required "Restore Purchases" affordance in Settings → Subscription.

Accessibility

PHASE CFeature 26

WCAG AA is a release gate, not a nice-to-have.

FR-MOBILE-A11Y-01

Every interactive control carries proper accessibility labels and roles; touch targets meet 44 pt (iOS) / 48 dp (Android) minimums.

FR-MOBILE-A11Y-02

Every screen is tested with VoiceOver and TalkBack with a logical navigation order.

FR-MOBILE-A11Y-03

Color contrast meets WCAG AA (4.5:1 body, 3:1 large text/UI) on both dark and light palettes.

FR-MOBILE-A11Y-04

System font scaling honored up to 200% on key screens without truncation.

FR-MOBILE-A11Y-05

Listing images carry descriptive labels so screen-reader users hear title and price.

Non-Functional Requirements

20 NFRs · All Phases

The quality bars the app must clear regardless of feature.

NFR-MOB-PERF-01

Cold start ≤ 2.5 s to first interactive frame on a mid-tier device (Pixel 5 / iPhone 12).

NFR-MOB-PERF-02

Warm start (background → foreground) ≤ 800 ms.

NFR-MOB-PERF-03

Sustained ≥ 55 fps on Kanban and feed scroll on reference devices.

NFR-MOB-PERF-04

Initial JS bundle ≤ 8 MB; total install ≤ 80 MB.

NFR-MOB-PERF-05

Crash-free-users rate ≥ 99.5% over rolling 7-day production windows.

NFR-MOB-SEC-01

Auth tokens live only in iOS Keychain / Android Keystore — never plain storage.

NFR-MOB-SEC-02

HTTPS-only networking; cleartext HTTP disabled at the OS configuration level.

NFR-MOB-SEC-03

Certificate pinning for the production API host with a documented rotation procedure.

NFR-MOB-SEC-04

No tokens, OAuth secrets, or PII in logs, crash reports, or analytics — enforced by a runtime safety filter.

NFR-MOB-SEC-05

No critical CVEs in production dependencies, verified continuously in CI.

NFR-MOB-A11Y-01

WCAG AA on every screen — contrast, dynamic type, screen readers, focus order.

NFR-MOB-A11Y-02

Platform touch-target minimums and accessibility roles/labels on all interactive controls.

NFR-MOB-RELEASE-01

Hot-fixes ship over-the-air in ≤ 30 minutes; rollback in ≤ 5; standard binary releases within ≤ 7 days (iOS) / ≤ 3 days (Android).

NFR-MOB-RELEASE-02

Every production binary has a GitHub Release with notes auto-extracted from the changelog.

NFR-MOB-RELEASE-03

Submissions comply with current Apple App Store Review Guidelines and Google Play policies.

NFR-MOB-RELEASE-04

Semantic version + build number visible in Settings → About for support reproducibility.

NFR-MOB-TEST-01

Unit-test coverage ≥ 80% statements / 70% branches on new modules.

NFR-MOB-TEST-02

E2E coverage at the correct level for every acceptance criterion — UI flows hit real device automation, logic hits service tests.

NFR-MOB-TEST-03

E2E suite runs on both iOS Simulator and Android Emulator in CI; smoke pack ≤ 8 minutes.

NFR-MOB-TEST-04

One requirements-traceability matrix spans web and mobile — every FR and NFR mapped to scenarios, 100% coverage.
